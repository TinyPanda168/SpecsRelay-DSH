# Product Hunt launch checklist

## 1. Account and product readiness

- [ ] Use a personal Product Hunt account. Company or branded accounts cannot post.
- [ ] Confirm the personal account has posting access. New accounts may need the onboarding/wait period shown by Product Hunt.
- [ ] Confirm the GitHub repository is public and its installation command works from a clean machine.
- [ ] Confirm the submission states that only DSH Desktop by anywhere-labs is supported, matching the current README.
- [ ] Confirm no secrets, personal paths, or private repository details appear in the gallery images.

## 2. Create the draft

- [ ] Select **Post** and enter `https://github.com/TinyPanda168/SpecsRelay-DSH`.
- [ ] Paste the product name, tagline, description, pricing, status, and topics from `SUBMISSION.en.md`.
- [ ] Add the creator's personal Product Hunt account as Maker.
- [ ] Upload `assets/thumbnail-240.png`.
- [ ] Upload `assets/gallery-01-deepseek-to-dsh.png`, `assets/gallery-02-workflow.png`, and `assets/gallery-03-native-experience.png` in that order.
- [ ] Exclude all files in `archive/` from the launch upload.
- [ ] Paste the Gallery captions.
- [ ] Add the first Maker Comment.
- [ ] Select **Create Draft** before choosing a launch date.

## 3. Preview review

- [ ] Product name contains no tagline or emoji.
- [ ] Tagline is not truncated in list view.
- [ ] Description stays within Product Hunt's 260-character limit.
- [ ] Thumbnail is readable at small size and has no thin text.
- [ ] All Gallery images render at 1270×760 with no cropping.
- [ ] Gallery has at least two images; a YouTube video is optional.
- [ ] Primary link opens the repository without requiring sign-in.
- [ ] The first image explains the product before the viewer reads the full description.
- [ ] Submission copy identifies DSH Desktop by anywhere-labs as the only supported client.

## 4. Schedule

- [ ] Choose a launch date only after the draft preview is complete.
- [ ] Product Hunt allows scheduling within the date range displayed in the current form; re-check before selecting.
- [ ] Reserve time to answer comments during the full Pacific-time launch day.
- [ ] Avoid scheduling another product from the same maker/company on the same day.

## 5. Launch day

- [ ] Replace `[PRODUCT HUNT URL]` in the prepared social posts with the live launch URL.
- [ ] Publish the short X/LinkedIn post and GitHub/community post after the launch is live.
- [ ] Pin the Maker Comment if Product Hunt provides the option.
- [ ] Answer setup and compatibility questions with the exact current README boundary.
- [ ] Ask for workflow feedback; do not ask directly for upvotes.
- [ ] Record recurring questions for README and onboarding improvements.

## 6. After launch

- [ ] Save the final Product Hunt URL in the repository About/homepage field if desired.
- [ ] Add a Product Hunt badge only after the launch page is live.
- [ ] Review link clicks, installation issues, and compatibility feedback.
- [ ] Do not schedule a minor relaunch as a new product; Product Hunt applies a significant-update and timing policy to relaunches.
